# 个人开发规则

## 核心信条
- 极致简洁：用最简单的逻辑实现最复杂的功能
- 面向对象：抽象、封装、复用；组合优于继承
- 设计模式：按需使用，避免过度设计；可读性与可维护性优先
- 统一规范：优先遵循 JSR 标准，认同并采用 Spring 的理念

## 架构与边界
- 分层清晰：`API → 应用/领域 → 基础设施`
- 依赖倒置：高层依赖抽象，低层实现细节
- 端口/适配器：以接口定义边界，适配器承载实现
- 稳定契约：公开接口稳定、向后兼容、幂等优先

## Spring 观点（默认取舍）
- 依赖注入（DI）与配置即代码：`@Configuration`、`@Bean` 明确依赖
- AOP 用于横切关注点：日志、审计、事务、权限
- 声明式事务：清晰划定事务边界，避免长事务
- 约定优于配置：沿用 Spring 约定，减少自定义复杂度

## 规范与 JSR
- Bean Validation 作为入口校验（JSR 380）：参数/DTO 必校验
- JPA/JDBC 访问遵循仓储模式：隐藏持久化细节
- REST 遵循 JAX-RS 精神：资源化、明确状态码与错误语义

## 编码准则
- 单一职责：每个类/方法只做一件事
- 面向接口编程：对抽象编程，最小可用接口
- 不可变优先：减少共享可变状态，线程安全优先
- 清晰错误处理：失败可预期，异常只用于异常路径
- 命名一致：业务语义优先，避免缩写与含糊

## 测试与质量
- TDD 倾向：核心业务单元测试必须覆盖
- 端到端验证关键路径：接口契约与幂等性校验
- 回归保护：为缺陷补测试，防止重复

## 性能与安全
- 基于度量优化：先量化，再优化，避免过早优化
- 输入校验与最小权限：零信任边界、严禁泄露密钥
- 可观测性：结构化日志、指标、追踪三件套

## 交付与协作
- 自动化构建/部署：可回滚、灰度发布
- 代码评审关注设计与风险：数据/事实驱动
- 语义化版本与变更记录：对外契约清晰
